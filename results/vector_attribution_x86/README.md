# x86 Linux 同排序内核复测

**明文快速 Top‑10 平均 1.774 ms，PPE 快速 Top‑10 平均 1.892 ms，密文开销为 +6.64%，配对 95% 区间 +6.07% 至 +7.22%。** P95 开销为 +5.10%。512 个查询重复 6 轮，明文快排在这批数据上的结果全部与严格真值一致，PPE 快排的 Recall@10 为 89.00%。[汇总](summary.json) · [9,216 条端到端记录](tls_samples.jsonl.gz)

实验使用独立的波兰 Vast.ai x86 实例，CPU 为 AMD Ryzen 5 5600X，与先前出现 −1.14% 的 CPU 型号相同。芯片支持 AES 和 AVX2。测试使用单线程 BLAS；三个条件共用同一 HPIC 进程、HPIS 进程、SQLite 文件和热 TLS 连接。公开 GloVe 100 维数据包含 20,000 个入库向量，β=0.25。每个查询的三个条件随机交叉，全部六种次序均衡出现。[代码与复现口径](../vector_attribution/README.md)

| 同一查询、同一台主机 | 平均时延 | P95 | HPIS 索引计算均值 |
|---|---:|---:|---:|
| 明文精确排序 | 1.849 ms | 2.445 ms | 342.50 µs |
| 明文 FP32 方向快排 | 1.774 ms | 2.340 ms | 269.58 µs |
| PPE 同核方向快排 | 1.892 ms | 2.460 ms | 297.81 µs |

只替换明文的排名分支，端到端时延就少了 74.68 µs，其中索引计算少了 72.92 µs。精确分支会扩大临界候选并以 FP64 复核近并列的顺序。原 x86 发布轮两个不同排名分支的 HPIS 存储阶段相差 88.13 µs。原样本没有更细的内核计时，本次相同 CPU 型号的对照量化了排名差异可以带来的收益。[历史样本阶段分解](../vector_attribution/historical_decomposition.json)

两个快速条件之间，PPE 共多用 117.89 µs。目标构造多用 22.72 µs，索引计算多用 28.23 µs，读取正文多用 25.23 µs，HPIC 打开与解包多用 33.33 µs，签名与余项合计多用 8.37 µs。近似排名可能取到不同的正文，密文记录也有额外认证封装。独立的热缓存同地址实验中，明文精确内核为 163.56 µs，明文同核快排 127.00 µs，PPE 快排 134.14 µs。对单位明文向量进一步省去按行模长缩放时，明文内核为 124.49 µs，PPE 与之相比增加 7.75%。这些内核均值单独测量。[4,096 条内核记录](kernel_samples.jsonl.gz)

同一套代码在 ARM64 上的同核端到端开销为 +4.51%（95% 区间 +3.76% 至 +5.24%）。两个独立平台都低于 10%。快速模式的精度取决于扰动参数和数据分布。[ARM64 结果](../vector_attribution/summary.json)

本次租用的节点为 61622569，公开报价约 0.0748 美元/小时。全部数据取回后已销毁，并确认从账户实例列表移除。首次结算读取约 0.024 美元，最终以服务商账单为准。[实例与费用](compute.json)

本次 x86 复测使用优化严格精排之前的[实际归因代码](benchmark_sources.tar.gz)。提取后运行 `python -m bench.vector_attribution --dataset /path/to/glove.hdf5 --rows 20000 --queries 512 --rounds 6 --kernel-rounds 2 --out /tmp/hpis-vector-attribution` 即可重建相同类型的随机交叉。每次创建新的加密密钥和算法要求的随机扰动。
