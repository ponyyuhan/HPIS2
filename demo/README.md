# 面向个人敏感数据的智能问答（演示）

同一个问题、同一份 10 万封邮件、同一个大模型，两条路径同时跑：

| 路径 | 做法 | 观众会看到 |
|---|---|---|
| 端侧直传普通云 | 每次提问把整个邮箱（邮件正文 + 附件）按 16 MB/批上传；云端逐批解析、按条件筛选、用同一模型对候选邮件现算向量排序，再调用大模型回答 | 端云传输约 275 MB、首字要等上传完、云端可读全部明文 |
| **端侧+HPIC+HPIS** | 终端生成 HMAC 检索令牌 + 密封目标向量；HPIS 在密文索引上筛选、在可信计算区内精确排序，只返回命中的几封密文 | 端云 ≈3 KB、云内 ≈几十 KB、只解密 K 封，回答与明文路径一致 |

每次提问结束后，页面还会在同一服务栈上做 60 次「明文检索 vs 密文检索」配对复测，现场给出密态检索的时延代价与 Top-10 是否完全一致。正式的 Linux 验收数据见「性能验收」页（`acceptance/`）。

## 启动

```bash
./HPIS2演示.command          # macOS 双击即可；Linux 直接运行
```

或手动：

```bash
python3 -m venv .venv-demo
.venv-demo/bin/pip install -e . -r demo/requirements.txt
.venv-demo/bin/python -m demo --open      # http://127.0.0.1:8780/
```

首次启动会在本机把邮箱加密预置进 HPIS（10 万封约 3–4 分钟，进度在页面上显示），之后启动约 10 秒。运行时数据在 `~/Library/Caches/hpis2-demo/`（Linux/Windows：`~/.cache/hpis2-demo/`），约 2.6 GB。拷贝到其他电脑时请连同 `demo/data/`（邮箱、向量与 bge 模型，约 0.6 GB）一起拷贝。

## 接入模型

默认通过 OpenRouter 调用 `qwen/qwen3.6-27b` 与 `google/gemma-4-31b-it`（需要环境变量 `OPENROUTER_API_KEY`），右上角可切换模型。OpenRouter 是第三方共享服务，首字时延偶有数秒抖动（实测 Gemma 更明显），可能让某一侧意外变慢；正式演示建议接 H200，或用 Qwen 并提前彩排（彩排的回答可在断网时回放）。

H200 部署见 [`demo/deploy/h200/README.md`](deploy/h200/README.md)。在 H200 上启动 vLLM 并建立 SSH 隧道后：

```bash
export HPIS_LLM_BACKEND=h200          # Qwen → 127.0.0.1:18081，Gemma → 127.0.0.1:18082
.venv-demo/bin/python -m demo --open
```

## 现场讲解建议（约 3 分钟）

1. 封面：一句话讲清目标 ——「云端大模型读懂你的私有数据，却看不见它」。点「进入现场演示」。
2. 选「项目纪要」，点「开始对比」。先看中间偏下的终端本地区：查询向量、HMAC 检索令牌、3 KB 的密封请求都在终端生成。
3. 看两条赛道：左边还在一批批上传邮箱（计时还在跑），右边「端侧+HPIC+HPIS」已经开始出字。
4. 点「端侧+HPIC+HPIS」回答里的引用编号，打开原邮件；切到「HPIS 中的样子」，看到同一封邮件在云端只是密文和令牌。
5. 底部结论条：端云传输减少数万倍、HPIS 只读取命中的 0.01% 密文、首字更快、密态检索代价与结果一致性（现场 60 次配对）。
6. 「云端视角」页：运维人员在普通云里搜「体检报告」立刻命中上百封；在 HPIS 存储里扫描全部密文，命中 0 条。
7. 「性能验收」页：Linux 服务器上的正式验收，各场景损耗均 < 10%。

快捷键：`1`–`6` 选预设问题，`Enter` 开始，`F` 全屏，`Esc` 关闭抽屉。

## 录制演示视频

点页面右上角 **录制视频**，选择 **此标签页** → **共享**。倒数 3 秒后开始录制，倒数本身不会录进去。演示完点 **停止录制**，MP4 自动保存到“下载”文件夹。

浏览器只允许在 https 或本机地址上录制：

- **本机打开**：`http://127.0.0.1:8780` 可以直接录。
- **从别的电脑打开**：要用 `https://<服务器 IP>:8781`。演示服务自签证书，第一次点「高级 → 继续前往」。在 8780 上点录制时，页面会给出跳转按钮。

## 断网或模型不可用时

先联网彩排一次，所有回答会被记录：

```bash
.venv-demo/bin/python -m demo.rehearse --models qwen gemma
```

现场如果模型服务不可达，页面会自动回放该问题的录制回答（状态显示「完成 · 回放」）；也可以强制离线：`HPIS_DEMO_OFFLINE=1 .venv-demo/bin/python -m demo --open`。检索、加密、传输统计始终是现场真实执行的。

## 哪些是实测，哪些是折算

- **实测**：终端向量化、SSE 令牌生成、密封、TLS 双跳、HPIS 检索与读取、HPIC 解密、普通云的解析与现算向量、模型生成、所有字节数。普通云与「端侧+HPIC+HPIS」使用同一嵌入模型与同一排序算法，两边交给大模型的证据邮件相同。
- **折算**：端云 / 云云链路按所选带宽与 RTT 计入时间（默认端云 1 Gbps、RTT 30 ms，云云 50 Gbps、RTT 0.5 ms），右上角可切换 5G / 4G 等条件。
- **可信计算区**：演示机上以受保护进程运行同一套 TEE 代码路径（向量密钥只交给 HPIS 可信区）；生产环境部署于机密计算硬件（如鲲鹏 TrustZone / AMD SEV-SNP，`hpis` 已支持 SNP 远程证明）。
- **数据**：邮箱是虚构人物「林舟」的模拟个人邮箱（含工作、客户、账单、体检、出行、学校等），人物、公司、金额均为虚构。

## 可能被问到的问题

**为什么密文检索几乎不比明文慢？** 密文检索在服务端多做的只是：HMAC 令牌比对（与明文标签同样是倒排表查找）、可信计算区内的向量密钥校验，以及 HPIC 对命中的 K 条记录做 AES-GCM 解密（10 条约几十微秒）。主要耗时——网络往返、TLS、鉴权、向量打分、读正文——两边完全相同。现场每题都会做 60 次明密文配对复测，正式数字见「性能验收」。

**以前有报告说密文比明文还快，是不是有问题？** 是基线不公平：旧报告的明文路径额外做了 FP64 精确复核，或在命中很少时走了一条明文专用捷径。本演示和新验收里明文与密文使用**同一套检索代码**（同一排序内核、同一倒排实现），只差加密本身，所以密文永远略慢、差值很小。

**密文向量检索会不会降低回答质量？** 软硬协同模式在可信计算区内用与明文完全相同的内核精确排序，Top-10 与明文逐条一致（页面上会显示「Top-10 与明文完全一致」），所以两边喂给模型的证据相同。纯密码学 PPE 模式（无需硬件信任）是近似检索，Recall@10 约 89%–94%，见验收页。

**TEE 是真的吗？** 演示机上，可信计算区由受保护进程运行同一套代码路径（向量密钥只在 HPIS 可信区内使用）；`hpis` 已实现 AMD SEV-SNP 远程证明，生产部署于机密计算硬件，硬件实测待对应设备。

**HPIC 能看到数据吗？** HPIC 是终端授权的可信计算区，只在本次请求内解密命中的 K 条（页面显示「HPIC 仅解密 10 封」）；HPIS 存储侧始终只见匿名标识、HMAC 令牌和密文（「云端视角」页可现场检索验证：命中 0 条）。

**网络是模拟的吗？** 链路时间按所选带宽与 RTT 折算（端云 1 Gbps / 30 ms，云云 50 Gbps / 0.5 ms，可切换），字节数、加解密、检索、模型生成全部是真实执行。即使把端云带宽设得很高，普通云也要上传整个邮箱并让云端看到全部明文。

**首次要上传加密数据吗？** 要，一次性：终端加密后上传（「云端视角」页顶部显示预置用时与密文体积），之后每次提问只发约 3 KB 的密封请求。
