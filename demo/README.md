# 个人智能计算平台2.0（演示）

虚构用户「林舟」的四台设备各自产生个人数据。同一个问题、同一个大模型，两条路径同时跑：

| 设备 | 数据 | 规模 |
|---|---|---|
| PC | 邮件（正文 + 附件） | 100,000 封 |
| 手机 | 相册照片（拍摄时间、地点、画面描述） | 397 张 |
| 手表 | 运动与健康记录（跑步、睡眠、周报、月报） | 2,834 条 |
| 车机 | 用车记录（行程、充电、导航、周报、月报） | 2,850 条 |

| 路径 | 做法 | 观众会看到 |
|---|---|---|
| 端侧直传机密计算平台 HPIC 1.0 | HPIC 1.0 不保存数据。每次提问，终端把这台设备的全部数据上传（邮件按 16 MB/批，共约 275 MB），在机密计算环境内解析、筛选、对候选现算向量排序，再调用大模型。手表、PC、车机的数据要先同步到手机（主设备），再由手机上传 | 每次都要上传整份数据，要等上传和解析完才能作答；没同步到手机的设备，数据用不上 |
| **HPIC 2.0：端侧 + 机密计算平台 + 安全存储平台** | 每台设备把数据一次性加密存入 HPIS（安全存储平台），各用一个匿名 AID。提问时终端生成 HMAC 检索令牌并密封目标向量，HPIS 在密文上检索，只返回命中的几条；HPIC（机密计算平台）只解密这几条交给模型（照片题把照片交给模型看图） | 每次只上传约 3 KB；四台设备的数据都用得上；HPIS 只见匿名密文，四个 AID 互不关联 |

每次提问结束后，页面还会在同一服务栈上做 60 次「常规检索 vs 密态检索」配对复测，现场给出密态检索的时延代价与 Top-10 是否完全一致。正式的 Linux 验收数据见「性能对比」页（`acceptance/`）。

## 启动

```bash
./HPIS2演示.command          # macOS 双击即可；Linux 直接运行
```

或手动：

```bash
python3 -m venv .venv-demo
.venv-demo/bin/pip install -e . -r demo/requirements.txt
.venv-demo/bin/python -m demo --open      # http://127.0.0.1:8780/
```

首次启动会在本机把邮箱和三台设备的数据加密预置进 HPIS（约 3–5 分钟，进度在页面上显示），之后启动约 10–30 秒。运行时数据在 `~/Library/Caches/hpis2-demo/`（Linux/Windows：`~/.cache/hpis2-demo/`），约 2.6 GB。拷贝到其他电脑时请连同 `demo/data/`（邮箱、设备数据、向量与 bge 模型，约 0.7 GB）一起拷贝。

## 接入模型

默认通过 OpenRouter 调用 `qwen/qwen3.6-27b` 与 `google/gemma-4-31b-it`（需要环境变量 `OPENROUTER_API_KEY`），右上角可切换模型。OpenRouter 是第三方共享服务，首字时延偶有数秒抖动，可能让某一侧意外变慢；正式演示建议接 H200，或提前彩排（彩排的回答可在断网时回放）。

照片题会把命中的照片交给模型看图作答，前提是模型支持图像输入（OpenRouter 上的 Qwen3.8-27B 和 Gemma 4 31B 都支持；Ollama 会在模型信息里标出 vision）。不支持时自动只给照片描述，也可以用 `HPIS_LLM_VISION=1` 或 `0` 强制。

H200 部署见 [`H200部署步骤.md`](../H200部署步骤.md) 与 [`demo/deploy/h200/README.md`](deploy/h200/README.md)。

## 现场讲解建议（约 6 分钟）

顶部依次是：主页 · 业务演示 · 方案架构 · 云端视角 · 性能对比。点「主页」随时回到封面。

1. 主页：一句话讲清目标——「云端大模型读懂你的私有数据，却看不见它」，右下是 HPIC 的信通院泰尔实验室增强级认证。点「进入业务演示」。
2. 业务演示 · 单端问答：最左侧标出 PC、手机、手表、车机四台设备，预设问题按场景分为日常生活、一生相随（相册）、运动健康。先选「会议总结」，点「开始对比」。两边都由手机提问。左边是端侧直传机密计算平台 HPIC 1.0：PC 的邮箱要先同步到手机，每次提问再由手机整个上传；右边是 HPIC 2.0：数据已加密存在 HPIS，只取命中的几条。
3. 每条赛道的用时是一行：上传、检索、模型作答，三段相加正好等于完整回答（从点击到最后一个字），精确到毫秒。两边用同一个模型，差距在上传和检索；密态检索在服务器上通常只要几毫秒。
4. 点回答里的引用编号打开原文；切到「HPIS 中的样子」，同一条数据在云端只是密文和令牌。
5. 换一生相随的「德国出差照片」：右边只取回几张命中照片的密文，HPIC 解密后交给模型看图整理；回答下方是照片缩略图，点开可看原图和它在 HPIS 中的密文。
6. 运动健康的「近一个月运动」、日常生活的「上月用车」同理。也可以现场改写问题（见下一节）。
7. 业务演示 · 多端协同：点顶部「多端协同」，选一个要用到几台设备数据的问题，在「HPIC 1.0 收到的数据」里选「仅手表数据」或「仅 PC 数据」，点「开始对比」。HPIC 1.0 只能用同步到手机上的那部分数据，回答会缺项，覆盖设备和关键信息都偏低；HPIC 2.0 四台设备的数据都在 HPIS，全部覆盖。
8. 方案架构：上半是云（终端云认证服务、HPIC 机密计算平台、HPIS 安全存储平台），HPIC 与 HPIS 合起来就是紫色虚线框里的 HPIC 2.0 个人智能计算平台；下半是用户的手机、PC、车机、手表。① 四台设备各用一个匿名 AID 加密上传，HPIS 里是四个互不关联的分区；②–⑦ 是一次提问的路径。
9. 云端视角：左边是终端本地数据（只在你自己的设备上，实名、原文可读），右边是存进 HPIS 安全存储平台后的样子。搜「体检报告」：终端本地检索命中上百条；HPIS 用 PC 的密钥令牌在密文上检索，命中最相关的 10 条，命中行亮起，但仍是密文，HPIS 不知道查的是什么、写了什么、是谁的。
10. 性能对比：Linux 服务器上的正式验收，密态检索相对常规检索的损耗均 < 10%。

快捷键：数字键 `1`–`9`、`0` 选预设问题，`Enter` 开始，`F` 全屏，`Esc` 关闭抽屉。

配色：默认深色；右上角太阳 / 月亮按钮在深色与米白浅色之间切换，浏览器会记住选择。也可以在地址后加 `?theme=light` 或 `?theme=dark` 指定。

## 现场改问题

- **自动判断问的是哪台设备**：照片、拍的 → 手机；运动、跑步、睡眠、半马 → 手表；开车、充电、去过某地 → 车机；其余 → 邮件。也识别「今年」「去年」「前年」「上个月」「最近一周」等时间，以及国家、城市名。
- **找不到时自动放宽**：条件太严没有结果时（例如相册里没有法国的照片），会去掉多余的条件按语义找最接近的，并在页面提示；模型会直接说明没找到什么。
- **不会卡住**：HPIC 1.0 最多对 100 条候选现算向量，并限时 6 秒；模型首字 25 秒内、整段回答 60 秒内必须结束；一次提问最长 90 秒。运行中可以随时点「停止」，下一个问题立即开始；新的提问也会自动停止上一个。
- 这些上限可用环境变量调整：`HPIS_DEMO_RUN_LIMIT_S`（90）、`HPIS_DEMO_FIRST_TOKEN_S`（25）、`HPIS_DEMO_ANSWER_LIMIT_S`（60）、`HPIS_DEMO_CLOUD_EMBED_BUDGET_S`（6）、`HPIS_DEMO_VERIFY_LIMIT_S`（6）。

## 录制演示视频

点页面右上角 **录制视频**，选择 **此标签页** → **共享**。倒数 3 秒后开始录制，倒数本身不会录进去。演示完点 **停止录制**，MP4 自动保存到“下载”文件夹。

浏览器只允许在 https 或本机地址上录制：

- **本机打开**：`http://127.0.0.1:8780` 可以直接录。
- **从别的电脑打开**：要用 `https://<服务器 IP>:8781`。演示服务自签证书，第一次点「高级 → 继续前往」。在 8780 上点录制时，页面会给出跳转按钮。

同一时间只能有一个提问在跑：在另一个标签页或另一台电脑上开始提问，会停止当前这一个。

## 断网或模型不可用时

先联网彩排一次，所有回答会被记录：

```bash
.venv-demo/bin/python -m demo.rehearse --models qwen gemma
```

现场如果模型服务不可达，页面会自动回放该问题的录制回答（状态显示「完成 · 回放」）；也可以强制离线：`HPIS_DEMO_OFFLINE=1 .venv-demo/bin/python -m demo --open`。检索、加密、传输统计始终是现场真实执行的。

## 哪些是实测，哪些是折算

- **实测**：终端向量化、SSE 令牌生成、密封、TLS 双跳、HPIS 检索与读取、HPIC 解密、HPIC 1.0 的解析与现算向量、模型生成、所有字节数。HPIC 1.0 与 HPIC 2.0 使用同一嵌入模型与同一排序算法；单端问答的预设问题两边交给大模型的证据相同。很宽泛的问题（候选超过 100 条）时，HPIC 1.0 先按关键词缩到 100 条再现算向量，两边取到的证据可能略有不同。多端协同里，HPIC 1.0 只拿得到同步到手机上的设备数据，证据自然更少。
- **折算**：端云 / 云云链路按所选带宽与 RTT 计入时间（默认端云 1 Gbps、RTT 30 ms，云云 50 Gbps、RTT 0.5 ms），右上角可切换 5G / 4G 等条件。
- **可信计算区**：演示机上以受保护进程运行同一套 TEE 代码路径（向量密钥只交给 HPIS 可信区）；生产环境部署于机密计算硬件（如鲲鹏 TrustZone / AMD SEV-SNP，`hpis` 已支持 SNP 远程证明）。
- **数据**：全部是虚构人物「林舟」的模拟数据，人物、公司、金额均为虚构。照片来自 Unsplash（按 Unsplash License 使用，作者署名见 `demo/data/devices/photos/ATTRIBUTION.md`），拍摄时间、地点按林舟的行程重新编排，画面描述由视觉模型生成。生成方法见 `demo/corpus/` 与 `demo/corpus/devices/`。

## 可能被问到的问题

**HPIC 1.0 和 HPIC 2.0 有什么区别？** 两者都在机密计算环境里处理数据。HPIC 1.0 不保存数据，每次提问都要由手机把数据上传，手表、PC、车机的数据要先同步到手机才用得上；HPIC 2.0 增加了安全存储平台 HPIS，每台设备的数据一次性加密存好，提问时只取命中的几条，四台设备的数据都能用上。

**为什么密态检索几乎不比常规检索慢？** 密态检索在服务端多做的只是：HMAC 令牌比对（同样是倒排表查找）、可信计算区内的向量密钥校验，以及 HPIC 对命中的 K 条记录做 AES-GCM 解密（10 条约几十微秒）。主要耗时（网络往返、TLS、鉴权、向量打分、读正文）两边完全相同。现场每题都会做 60 次配对复测，正式数字见「性能对比」。

**以前有报告说密态检索比常规检索还快，是不是有问题？** 是基线不公平：旧报告的常规检索路径额外做了 FP64 精确复核，或在命中很少时走了一条专用捷径。本演示和新验收里两边使用**同一套检索代码**（同一排序内核、同一倒排实现），只差加密本身，所以密态检索永远略慢、差值很小。

**密态向量检索会不会降低回答质量？** 软硬协同模式在可信计算区内用与常规检索完全相同的内核精确排序，Top-10 逐条一致，所以两边喂给模型的证据相同。纯密码学 PPE 模式（无需硬件信任）是近似检索，Recall@10 约 89%–94%，见性能对比页。

**照片也是加密的吗？** 是。照片本身以 AES-256-GCM 密文存在 HPIS；拍摄时间、地点、类别变成 HMAC 检索令牌；画面内容的向量在可信计算区内比较。只有命中的几张由 HPIC 解密后交给模型看图。

**四台设备的数据为什么不能被关联？** 每台设备用自己的匿名标识 AID 和密钥上传。HPIS 里同时存着多个匿名租户的数据（「云端视角」页右侧），既看不出哪几个 AID 属于同一个人，也读不出任何内容。

**TEE 是真的吗？** 演示机上，可信计算区由受保护进程运行同一套代码路径（向量密钥只在 HPIS 可信区内使用）；`hpis` 已实现 AMD SEV-SNP 远程证明，生产部署于机密计算硬件，硬件实测待对应设备。

**HPIC 能看到数据吗？** HPIC 是终端授权的可信计算区，只在本次请求内解密命中的几条（页面显示「HPIC 仅解密 10 封」）；HPIS 存储侧始终只见匿名标识、HMAC 令牌和密文（「云端视角」页可现场检索验证：检索照常命中，但命中的只是匿名 AID 下的密文）。

**网络是模拟的吗？** 链路时间按所选带宽与 RTT 折算（端云 1 Gbps / 30 ms，云云 50 Gbps / 0.5 ms，可切换），字节数、加解密、检索、模型生成全部是真实执行。即使把端云带宽设得很高，HPIC 1.0 每次也要上传全部数据。

**首次要上传加密数据吗？** 要，一次性：终端加密后上传（「云端视角」页顶部显示预置用时与密文体积），之后每次提问只发约 3 KB 的密封请求。
